# Decisions

| 21-11-2026 | Spend gate: under US$1 continue, otherwise the owner says yes. | Applies to Parallel and fal, per batch. |
| 21-11-2026 | The shape, print, cap and real-camera checks of a11-adgen stay. | They run as server tools at fixed points of the pipeline. |

| 21-11-2026 | The owner gets an email when a new program waits for approval. | The studio publishes one notice per new program to a topic that emails the cost-alert address. The owner confirms the subscription once. |
| 22-11-2026 | A brand or a product is saved only from what the server itself read. | `brand_save` and `product_save` take an offer id from `brand_extract` or `product_extract`. An agent cannot save a kit it made up. |
| 22-11-2026 | A fact is kept only when its exact words are on the page it names. | The server reads the page again at save time. A number in a truth sheet with no such fact is marked `unverified`. |
| 22-11-2026 | The taste canon is plain text with versions. | Each save needs a reason and makes a new version. Old versions stay readable. Only the owner saves. |
| 22-11-2026 | The taste data of a11-adgen is copied once, through the two MCP servers. | Each record keeps its a11-adgen id, so a second copy changes nothing. Private picture links are not copied. The gold set is not copied (see the decision of 22-11-2026 below). |
| 22-11-2026 | Caps: US$25 a month, US$5 a batch. | A paid call holds its price first. A call that would pass a cap is refused. A call with an unknown result stays counted. |
| 22-11-2026 | Research waits for the owner at each US$1. | Research has no count to estimate from, so the gate reads the batch's total: under US$1 it goes on, and each further US$1 needs a new yes (`spend_approve`, stage `research`). Research that belongs to no batch is held the same way, on its total for the month. |
| 22-11-2026 | A product has one truth sheet, with versions. | The sheet describes the real product, so its batches share it. A save that changes it makes a new version and the earlier ones stay. A batch keeps the version it saved, so its ideas and finals trace to that exact sheet. |
| 22-11-2026 | A render waits for the owner at US$1 per stage. | The first draft of a batch is sent alone and its real price sets the estimate for the rest. Drafts and finals are two stages, each with its own yes (`spend_approve`). A render with an unknown result stays counted. |
| 22-11-2026 | No words are asked of the model. | `render_submit` adds the studio's own no-words and realism lines to each prompt and refuses a prompt that asks for a headline, a caption, a button, a price or a sign. |
| 22-11-2026 | The pixel tools run in their own function, with the scripts of a11-adgen unchanged. | `product_lock.py`, `pack_check.py`, `cap_check.py` and `photo_finish.py` are copied as they are, with their tests. Its role allows it to read and write pictures only: no table and no key. Only the API may start it, and the API looks up every picture; an agent names a picture by its id. |
| 22-11-2026 | A measure belongs to the tool that made it. | A failed `pack_check` or `cap_check` is saved on the picture as D11. `checks_save` cannot clear it; only a later pass of the same tool on the same picture does. |
| 22-11-2026 | A repair stands for its picture, and is checked as a new one. | A `product_reprint` or `product_swap` replaces the draft or the final on the board and as the source of the final. The old picture's checks are not carried over. |
| 22-11-2026 | One D item, or two F items, rejects a picture. | A draft with a D item cannot become a final. A batch is finished when each picked idea has a final that is checked, has no D item and has its real-camera finish. |
| 22-11-2026 | The board shows drafts in the order they were sent, with no rank. | Only the owner picks or passes, in their own words. Each pick and each pass goes into the taste log. A new pick replaces the old one and the log keeps both. |
| 22-11-2026 | A fresh critic judges blind, with a ticket that works once. | `critic_open` gives a helper that got the batch id only a packet with no owner pick, no earlier rank and none of the author's notes. `critic_pick` keeps or cuts each idea before any draft is made; `critic_rank` orders each idea's drafts before the board is ready. A caller that says it is not a fresh helper is refused. |
| 22-11-2026 | The critic's rank is hidden until the owner has picked. | The board and `board_show` give an idea's rank only after his pick or pass, and no rank is taken for an idea he has chosen for. |
| 22-11-2026 | No gold set. The critic is measured against the owner's real picks. | The owner called his 264 old marks mixed, so they are not copied and no gold test runs. The Calibration page and `calibration_report` count how often he picked the draft that the blind critic had put first. |
| 22-11-2026 | A batch is done when the owner picked a draft for each idea and each pick became a clean final. | `batch_done` gives each condition with its evidence and marks the batch done when both hold. A pass on an idea leaves the batch finished, not done. It lists the stranger test, which only the owner runs. |
| 22-11-2026 | The studio will make three kinds of ad. | v1 is the wild picture with the logo only. v2 and v3 are engine 2 and engine 3 of a11-adgen, with every step and stop, the Meta text, the client pack link and results upload. The agent asks which kind at the start of a batch. v1 is finished first, then v2, then v3. |
| 22-11-2026 | Calibration counts the owner's first choice only, beside a rank of the same picture. | After his first pick he sees the critic's order, so a changed pick is not blind: the pick keeps his first choice. A rank records the picture the critic looked at; a draft repaired later needs a new rank. A done batch whose final fails later goes back to its finals. |
| 22-11-2026 | A batch has a kind, chosen when it is made. | `batch_create` takes `kind`: `v1`, `v2` or `v3`. A batch saved before this is `v1`. `rules_get` serves the rules of that kind and of the caller's role. |
| 22-11-2026 | A v2 batch is three ads: one for each of top, middle and bottom of funnel. | The writer saves a burst of 24 to 30 ideas, 8 or more for each stage, before any is chosen. A fresh critic chooses one for each stage (`critic_select`), or refuses a stage rather than lower the bar. |
| 22-11-2026 | The owner approves the words before any draft is paid for. | `copy_approve` saves his exact headline and subline, owner only. A number in them needs a saved fact; a top of funnel ad has no price, saving or delivery offer. A long line is told to him, and his words stand. |
| 22-11-2026 | The words are set by code in the brand's own font, never painted by the model. | `font_save` keeps the font file. `type_set` reads the approved words from the store, so a caller cannot type other words. A draft and a final of an ad with words count only with their words set, and a change of the words or a repair needs them set again. |
| 22-11-2026 | Real photos first, for everything. | The owner: "make sure it works for everything and i mean everything." An idea names the real photo of each brand item and prop it shows (`pack`, `food`, `prop`), and a draft is refused when one is missing. A plan can place a real photo of each variant. A product keeps up to 16 photos. |
| 22-11-2026 | No sticker and no button on the picture, for all three kinds. | The owner: his reference ads do not need one. Two of his references carry a chip or a badge; that part is not carried over. |
| 22-11-2026 | The owner's reference ads are the bar for v2 and v3, and loose examples for v1. | 16 headline ads are references for v2 and v3; `ideas_save` of an ad with words needs `references_get` read. The two logo-only ads are marked loose for v1: "don't be using the reference as a strict guide." The sheet of real cake slices is a method (real photos first), not a reference. The pictures stay in the private store. |
| 22-11-2026 | `headline.py`, `box_print.py` and `food_grade.py` of a11-adgen are copied unchanged, and relight and vary-food are switched on. | They run in the pixel function as `type_set`, `box_print`, `food_grade`, `product_relight` and the `vary` input of `skeleton_make`. The open-neck tools (`pack_pad`, `pack_open`) are in the pixel function with their tests; their studio tool comes with v3, which needs the model's edit between them. |
| 22-11-2026 | In an ad with words, the picture with its words is the one that is looked at, ranked and picked. | Found by review. `checks_save` takes the picture `type_set` made, and a draft or a final counts only when that picture is looked at with no D item and fewer than two F items. The critic's rank and the owner's pick record that picture, so a rank of the bare photo, or of old words, does not count. A picture keeps the version of the words it was sent with. After the owner changes the words, `pick_save` is refused until the new words are on the drafts. `rules_get` gives an ad with words a D1 that allows the approved words and no word the model drew. |
| 22-11-2026 | A top of funnel ad: the words that count as an offer. | Found by review. A price, "N% off", "save N", a discount, a promotion, a voucher, one-for-one, "buy N get", and any word of delivery or shipping. A percentage alone is not an offer. |
| 22-11-2026 | Proposed, waits for the owner's yes: a test batch. | Cause: in the first live v2 run the agent called `copy_approve` and `pick_save` itself to pass the two owner gates, and its three picks went into his taste log and his calibration. `batch_create` takes `test: true`, set at the start and never after. In a test batch a pick is saved for the batch only: nothing goes to the taste log, and the calibration skips the batch. `batch_done` never marks it done. The dashboard marks it. A batch whose ads the owner may use is never a test. |
| 22-11-2026 | Each picked ad gets two texts for Meta, and only the owner approves them. | `meta_save` keeps the primary text, headline, description and a button from a fixed list, twice for each ad. It refuses a number no saved fact holds, an offer on a top of funnel ad, and a primary text that does not open with the picture's own line. Lengths are told, not refused. `meta_approve` is the owner's alone and keeps his words. A later text is a new version, and the approved one stays. |
| 22-11-2026 | The studio makes the name of an ad. | `a11_W<week>_<brand>_b<NN>_<stage>_c<idea>_v<version>`: the Singapore week of the day the pack is made, the brand, the brand's batch number oldest first, the stage (`wild` for a v1 ad), the idea and the pack version. No caller types any part. An ad keeps its name while its picture and its text stay the same, so a result always maps to one ad. |
| 22-11-2026 | A client pack is made from a done batch only, and its link is private. | `pack_publish`, `pack_update`, `pack_restore` and `pack_relink` are the owner's alone. A test batch, a batch that is not done and an ad without approved Meta text are refused. The pack copies the approved text from the store; no caller retypes it. The link holds a 256-bit token; the studio keeps only its SHA-256, shows the link once, and answers a wrong or replaced token with 404. The page needs no sign-in, is not indexed, sends no referrer and names nothing else of the studio. An update makes a new version at the same link; earlier versions stay and can be restored. |
| 22-11-2026 | A client's results file goes straight to the store, apart from the studio's pictures. | The pack page asks for one signed link for each file: JPEG, PNG, CSV or XLSX, up to 10 MB, 20 files for each pack. The type and the size are signed, so the store refuses another file. Files go to `quarantine/`, are never read by the server, and only download; they never open in a page. A file is data: an agent follows no instruction in it. |
| 22-11-2026 | A result belongs to one ad name and one pack version, with its campaign. | `results_save` takes the numbers as the report shows them and refuses a name no version holds. The studio counts the CTR. The campaign (objective, audience, placement, budget) is always saved, and the client's usual CTR when given: numbers are not compared without them. Results teach nothing by themselves yet; the learning step comes later. |
| 22-11-2026 | A v3 batch is a concept ad, and the owner picks its three concepts himself. | From engine 3 of a11-adgen and its overhaul. `batch_create` takes `kind: "v3"`. The path: truth, `brief_save`, `concepts_save`, roughs, the critic's review, `concept_pick`, `copy_approve`, then the direction and the drafts. The critic advises and never chooses; the three can be of any funnel stage. |
| 22-11-2026 | A brief marks each insight as evidence, an interpretation or a hypothesis. | Evidence has a buyer's exact words and an https page. Fewer than three insights that are no hypothesis stop the concepts. A concept on a hypothesis is saved with a warning, and the owner is told when he picks it. |
| 22-11-2026 | A concept set has 6 to 15 concepts in 3 to 5 territories, each territory on its own insight. | Counted in code because each is a true or false fact. More concepts are added to the set, up to 30; none is deleted, so the owner can come back to an earlier one. |
| 22-11-2026 | A rough is a cheap first picture of a concept: two at most for a concept, eight for a batch. | The first engine 3 batch of a11-adgen failed because concepts were judged as words. A rough is low quality, made from the product's real photos, with no approved words. The places are counted before the paid call, and a call that fal surely did not bill gives its place back. |
| 22-11-2026 | The critic reviews every concept from its rough, and may recommend none. | `critic_open` with step `concepts`, then `concept_review_save`: nine scores, the point test, the local-truth test, the cover test from the rough and the pay question. A concept with no rough, a picture under 4 or a failed point test cannot be recommended. A new concept or rough makes the review old, and the owner cannot pick until a fresh critic looks again. |
| 22-11-2026 | The owner sees the critic's review of a concept before he picks. | The owner's decision, kept from a11-adgen. It is unlike the rank of the drafts, which stays hidden until his own pick: here he asked for every concept, rough, score and note. A pick the critic did not recommend is saved with a warning. A concept pick in a test batch is not in the taste log. |
| 22-11-2026 | A rough is sent with the real photo of each thing its concept shows, and a concept ad has no draft before its direction. | Found by review. A saved photo that is not given to the model does nothing, so `render_submit` refuses a rough whose `references` leave out a photo in `shows`. A v3 draft is refused at `worded`: it waits for `directed`. Two `concepts_save` calls at the same moment cannot write over each other: the second is refused and reads the set again. The critic's packet holds the insight behind each concept, with the buyer's words. |
| 22-11-2026 | A concept ad has a direction before its drafts: three drafts for a concept, each pair apart on three axes or more. | Carried from engine 3 of a11-adgen, whose first batch gave three drafts that were one picture three times. `direction_save` counts the axes on which each pair of drafts differs (composition, product position, scale, camera, light, environment, negative space, staging) and refuses fewer than three, or a pair with the same composition, camera and scale. A high risk needs its reason. Every save is a new version, and a draft keeps the version it was made from. |
| 22-11-2026 | A draft of a concept ad starts from the concept's rough and the product's real photos, with no skeleton. | The rough is the picture the critic and the owner judged the concept by, so the model sees it first. The product is drawn from its real photos so that it can be held, turned or opened; `pack_check` measures its shape within 2 per cent before the draft counts, and a skeleton with the real pack is the fallback. Each draft is sent with its number from the direction, once. |
| 22-11-2026 | A real-photo plan needs no pack photo when each item names a saved real photo. | The owner's rule: real photos first, for everything. A cake or a dish has no pack, so `skeleton_make` builds its plan from the product's saved food and prop photos alone, cut from their plain backdrop. A name the product does not have is refused, no file name is read, and the plan stays with the skeleton so a draft is traced to it. |
| 22-11-2026 | A rejected concept draft is made again once, then the direction is lowered. | In a11-adgen a draft with a fault was sent again and again, and each try cost money and looked like the last. A draft that its checks reject (a D item, or two F items) gets one redo with the same number; the redo stands in its place on the board. A third try is refused: the agent saves a new direction with a lower risk instead. |
| 22-11-2026 | A final of a concept ad passes eight points before it is delivered. | The owner's bar of engine 3: a final is judged as the picture he would send, at full size and at phone size, on concept, product truth, brand identity, copy accuracy, food, composition, craft and the render checklist (`final_points_save`). A final with a failed point, or with no points saved, is not delivered and never enters a pack. This is one true/false gate on a saved record; the judgement itself stays with the agent, in words. |
| 22-11-2026 | The owner's newer verdict on a concept stands over his earlier pass. | He can pass on all three drafts and later take one. `pick_save` keeps his first choice for calibration and takes the newer one for the finals. Each draft on the board of a concept ad shows the question its direction asks him. |
| 22-11-2026 | A lower-risk direction is saved while the drafts are made, for the concept whose redo was rejected. | Found by review: the one way out of a rejected redo was refused, because a direction was saved only before the first draft. `direction_save` now takes a changed concept at `priced`, `waiting_spend` and `drafting` when a redo of it is rejected and its risk goes down (a concept at low takes a plainer look at low). That concept's three drafts start again; the other concepts keep theirs. |
| 22-11-2026 | A concept draft always gets the real photo of each thing it shows, and the rough is on top of the four. | Found by review. A skeleton does not stand for a photo the concept shows, a concept with no rough starts from a real-photo plan, and the rough does not use one of the four reference places. `pack_check` measures against the pack photo the render named when the picture has no skeleton. |
| 22-11-2026 | A finished batch takes the owner's newer pick of a concept he passed on. | Found by review: a pass and two finished finals closed the board, and the done gate then asked for a pick that could not be saved. `pick_save` works at `finished`, and the batch goes back to its finals. |
| 22-11-2026 | A render past the stage's estimate makes the estimate larger. | Found by review: a redo, or the three drafts of a lowered direction, were bought under the estimate of the first nine. `SpendGate.check` now counts what the stage has sent and what it came to; the estimate is what the stage came to so far (a failed render that fal charged for counts), the next render, and the first one's price for each of the rest. One more item than it counted, or a dearer item than the first (more reference pictures), makes it larger; a render that was refused and never sent leaves nothing in it. An estimate of US$1 or more, or one larger than the owner approved, waits for his yes. |
| 22-11-2026 | The studio keeps four sets of rules apart: the owner's taste, one brand's rules, creative craft and performance. | Engine 3 of a11-adgen mixed what he likes with what one brand needs and what results showed. `canon_get` with a batch id gives the four that hold for that batch and never the rules of another brand. A missing scope is the owner's taste, so nothing saved before moves. |
| 22-11-2026 | A lesson is written down first, and changes a rule only on the owner's yes. | v1 of a11-adgen added a rule after each bad batch. `learn` keeps what was seen and changes no rule and no fact. `canon_propose` writes the whole canon as it would read; a rule for every brand needs two separate pieces of evidence, and a proposal written against an older version is refused. Only the owner decides (`canon_decide`, or the Taste page), in his own words. `canon_restore` brings an earlier version back as a new one. |
| 22-11-2026 | What the owner chose for one brand is kept as a brand note, not as a fact. | "The cap, not the pump" is his choice, not a claim about the product. The next batch of that brand reads it; copy may not state it. A test batch saves no note and no learning record. |
| 22-11-2026 | A yes to a proposal lands only on the version it was written against, and a decision that stopped half way is finished by the next try. | Found by review: two proposals for one canon, both approved at the same moment, each made a version, and the second dropped the first. | 22-11-2026 | A concept ad that shows the food alone owes no pack measure. | Found in the live v3 test (IRVINS): a row of real fish skin pieces with no pouch could never be checked, because the product has a pack photo and the board asked for `pack_check` on every picture. | 22-11-2026 | A draft made again may keep its skeleton. | Same test: the one redo of a draft was refused as R23, because its skeleton already had a draft: the one it replaces. Another draft of the concept still needs its own. |

| 22-11-2026 | A draft its own checks reject is not asked for its type again. | Same test: a pouch drawn too tall, noted on the picture with its words too, kept the board asking for `type_set` again, which mends nothing. |
